\section{Offline Routing with Fixed-Window Subscriptions (Stage 1)}
\label{sec:offline-stage1}

This section formalizes the Stage~1 offline optimization problem for our hybrid inference system.
Stage~1 considers one or more subscription plans with fixed-window quotas (\(S_Q\)) and a pay-per-token API (\(S_A\)).
The objective is to compute the minimum possible API cost for a given request trace when subscription limits are known in advance.

\subsection{Problem Overview}
We consider a single system serving one or more models. Each request can be served either by a subscription \(S_Q\) (zero marginal cost, limited by a fixed-window count) or by a pay-per-token API \(S_A\) (unlimited capacity, fixed per-model pricing). The subscription fee is treated as sunk and excluded from the objective.

Many commercial subscriptions enforce rate limits over rolling windows (e.g., \(160\) requests per \(3\) hours). To obtain a tractable closed-form offline oracle, we approximate rolling limits using \emph{disjoint, fixed time windows} anchored at a reference time. This is a relaxation of rolling-window constraints and therefore yields an optimistic lower bound on the achievable API cost.

\subsection{System Model}
\paragraph{Requests.} We are given a set of requests \(\mathcal{R} = \{1,\dots,n\}\). Each request \(i\) has:
\begin{itemize}
  \item Arrival time \(a_i\) (seconds since epoch);
  \item Model type \(m(i)\) from a model set \(\mathcal{M}\);
  \item Input tokens \(n_i^{\text{in}}\) and output tokens \(n_i^{\text{out}}\).
\end{itemize}
\paragraph{Providers.}
\begin{itemize}
  \item Fixed-window subscription(s) \(S_Q\): let \(\mathcal{P}\) be the set of subscription plans. Each plan \(p \in \mathcal{P}\) is characterized by a window length \(W_p\), a per-window quota \(Q_{\text{win},p}\), and a fixed window alignment \(t_{0,p}\). Define the window index function
  \[
    \operatorname{win}_p(t) = \left\lfloor \frac{t - t_{0,p}}{W_p} \right\rfloor.
  \]
  In each window \(k\), plan \(p\) can serve at most \(Q_{\text{win},p}\) requests at zero marginal cost; quota does not carry over. A daily quota is the special case \(W_p = 24\) hours with \(t_{0,p}\) aligned to midnight (in a chosen timezone).
  \item Pay-per-token API \(S_A\): unlimited capacity; fixed per-model prices \(p_m^{\text{in}}, p_m^{\text{out}}\) per 1K tokens. The API cost for request \(i\) is
  \[
    c_i^{\text{API}} = \frac{n_i^{\text{in}}}{1000}\,p_{m(i)}^{\text{in}} + \frac{n_i^{\text{out}}}{1000}\,p_{m(i)}^{\text{out}}.
  \]
\end{itemize}
\paragraph{Compatibility.}
Real-world subscriptions only cover specific models. We assume each model \(m\) is eligible for at most one subscription plan \(p(m) \in \mathcal{P}\) (or none). Equivalently, each request \(i\) is compatible with at most one plan \(p(i)=p(m(i))\); if no plan exists, the request must use the API.
For example:
\begin{itemize}
  \item OpenAI plan: \(\{ \texttt{gpt-5}, \texttt{gpt-5.1} \}\).
  \item Anthropic plan: \(\{ \texttt{claude-4.5-opus}, \texttt{claude-4.5-sonnet}, \texttt{claude-4.1-opus}, \texttt{claude-4.1-sonnet} \}\).
\end{itemize}
\paragraph{Assumptions.}
\begin{itemize}
  \item Subscription fees are sunk costs and omitted from the objective.
  \item \(S_Q\) has no concurrency bottleneck; only the per-window quota \(Q_{\text{win},p}\) matters.
  \item API pricing is fixed per model; we do not model multiple competing APIs.
  \item Requests are independent; there are no ordering constraints.
\end{itemize}

\subsection{Optimization Problem}
For each request \(i\), define binary routing variables \(x_i^Q, x_i^A \in \{0,1\}\) with the assignment constraint \(x_i^Q + x_i^A = 1\). If request \(i\) is not compatible with any plan, we require \(x_i^Q = 0\) (and thus \(x_i^A = 1\)). The objective is to minimize total API spending:
\[
  \min\; \sum_{i\in\mathcal{R}} x_i^A\,c_i^{\text{API}}.
\]
For each plan \(p\) and window index \(k\), define the request set
\[
  \mathcal{R}_{k,p} = \{ i \in \mathcal{R} \mid p(i)=p \land \operatorname{win}_p(a_i)=k \}.
\]
Subject to the per-window quota constraint for every plan \(p\) and window \(k\):
\[
  \sum_{i\in\mathcal{R}_{k,p}} x_i^Q \le Q_{\text{win},p}.
\]

\subsection{Closed-Form Optimal Solution}
Since each request consumes one unit of quota on \(S_Q\), Stage~1 reduces to a knapsack problem with identical item weights within each \((p,k)\). The optimal solution is obtained by sorting requests by API cost in descending order per plan-window and assigning the top \(Q_{\text{win},p}\) to \(S_Q\); remaining requests use \(S_A\).

\paragraph{Algorithm.}
For each plan \(p\) and window \(k\):
\begin{enumerate}
  \item Collect requests \(\mathcal{R}_{k,p}\).
  \item Sort in descending order by \(c_i^{\text{API}}\).
  \item Assign the top \(\min(Q_{\text{win},p}, |\mathcal{R}_{k,p}|)\) requests to \(S_Q\); assign the rest to \(S_A\).
\end{enumerate}
\paragraph{Proof of Optimality.}
Selecting the top-\(Q_{\text{win},p}\) items by value within each plan-window is optimal when all weights are equal; any deviation can be improved by swapping a lower-cost request using \(S_Q\) with a higher-cost request using \(S_A\).
\paragraph{Complexity.}
Sorting dominates: \(\mathcal{O}(n\log n)\) time and \(\mathcal{O}(n)\) space.

\subsection{Multi-Model and Multi-Plan Quotas}
Many subscription plans cover multiple models and share a single message budget. Stage~1 naturally prioritizes higher API-cost models within each plan-window.

\paragraph{Example.}
Consider the \textbf{Anthropic plan} shared by multiple models. Suppose in a single window we receive:
\begin{itemize}
  \item \(20\) requests for \texttt{claude-4.5-opus} (high API cost);
  \item \(50\) requests for \texttt{claude-4.5-sonnet} (medium API cost);
  \item \(30\) requests for \texttt{claude-4.1-sonnet} (low API cost).
\end{itemize}
If the window quota is \(Q_{\text{win}} = 45\), the algorithm sorts all \(100\) requests by \(c_i^{\text{API}}\), assigns all \(20\) \texttt{claude-4.5-opus} requests to \(S_Q\), then fills the remaining \(25\) slots with the most expensive \texttt{claude-4.5-sonnet} requests. The rest are routed to \(S_A\).
