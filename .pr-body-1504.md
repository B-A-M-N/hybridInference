## Summary

Implements the sanitized response headers from #1504 — the one leg of that issue still open on `dev` (the `api_logs` identity columns already landed; the local FI gateway log half belongs to the external freeInference repo).

The gateway resolves the served adapter, endpoint and provider before it dispatches, but that identity never reached the caller: `owned_by` is only a provider label, and the small-budget Anthropic reroute can serve a different model than the one the client named. Four response headers now carry what dispatch already knows, on both inference surfaces, streaming and non-streaming:

| Header | Value |
|---|---|
| `X-FI-Requested-Model` | the model string the client sent |
| `X-FI-Served-Model` | the model that actually served (post-alias/reroute) |
| `X-FI-Served-Endpoint` | the sanitized logical endpoint id |
| `X-FI-Served-Provider` | the provider label of the serving adapter |

## Changes

- **`served_identity.py` (new)** — header names, the builder, and the endpoint sanitizer.
- **`anthropic_messages.py`** — the identity is built once after dispatch resolution (post-reroute), merged into the streaming `sse_headers` and the non-streaming `JSONResponse`. Both paths expose the exact served endpoint, because this surface resolves its adapter before dispatch.
- **`completions.py`** — non-streaming sets the headers after the response enriches `routing` from the adapter's `_routing` blob (exact identity); streaming paths set them from the static pre-dispatch view (requested + served model always; endpoint/provider only when the route has a single backend, mirroring the existing `get_single_route_provider()` limitation — multi-backend routes pick the adapter lazily after the headers are committed, and the exact identity still reaches `api_logs` through `_routing`).

### Sanitization

The endpoint header accepts only the registry's sanitized shapes — `local-<port>` and single-label `<service>-api`. A LAN octet stamp (`10-api`), a hostname (`gpu-7-api`), or an admin-supplied `route_id` kept verbatim degrades to the provider label, so private topology never reaches a caller-visible header (`api_logs` keeps the full id). Verified by a parametrized test.

### Auto selection concealment preserved

Auto mode deliberately does not tell the caller which model serves an auto request (the response names the auto model; `hide_served_model` scrubs error text). That concealment now extends to the headers: auto-served responses carry only `X-FI-Requested-Model`. Pinned in `test_auto_mode_surfaces.py` on both surfaces.

### Not changed

- No routing, billing, or log-write behavior is touched. Existing `X-Provider` probe headers are untouched.
- Embeddings/responses surfaces are left for a follow-up if wanted; the issue's motivating workloads (chat loop attribution, the Anthropic reroute) are covered.

## Tests

- `tests/servers/test_served_identity_headers.py` (new, 15): header presence on `/v1/messages` non-streaming + streaming, chat completions non-streaming + streaming, endpoint sanitizer parametrized cases, omit-when-absent builder cases.
- `test_anthropic_messages_reroute.py`: the reroute test now also asserts `X-FI-Requested-Model` ≠ `X-FI-Served-Model` — the issue's core case.
- `test_auto_mode_surfaces.py`: auto-served responses carry no served-identity headers (both surfaces).
- Focused suites green (54 + 292 + 23 + 76); `make test` 8608 passed with only the 5 known local-environment failures (`classify_changes` git-hook env ×3, `routewise_hedging` flake, `routewise_example_runtime` boot — all pre-existing, untouched by this change). `make format` / `make lint` clean.

Closes #1504 (together with the already-merged `api_logs` columns) on the HI side.
